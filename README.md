# 途记

把不同目的地的旅行攻略钉在同一张地图上。可以按手机号登录、写攻略、留言和回复、分享到微信 / QQ / 微博，也可以在地图上共享自己的位置。手机和电脑使用同一套页面，布局会随窗口变化。

## 本地运行

需要 Node.js 22.13 或更新版本。

```bash
npm install
npm run dev
```

打开 <http://localhost:3000>。

演示环境不会发送短信。在登录页获取验证码后，6 位数字会直接出现在页面上。也可以输入 `13800000001`，验证通过后会进入已经写过大理和西湖攻略的「林夏」。

```bash
npm test
npm run typecheck
npm run build
npm start
```

数据库是项目目录下的 `data/tuji.sqlite`，第一次启动时自动建表并写入示范攻略。删除这个文件再启动，会重新播种。

## 现在能做什么

- 地图上查看全部攻略，按地区和关键词筛选，点标记或「在地图上」定位。
- 手机号 + 6 位验证码登录。新号码自动注册，登录状态保留 30 天。
- 发表、编辑、删除自己的攻略。位置用点地图或浏览器定位来钉。
- 留言，以及对留言再次回复。可以删除自己的留言。
- 分享：微信（普通浏览器给二维码，微信内提示使用右上角菜单）、QQ、微博、复制链接。手机浏览器如果提供系统分享，也会出现该按钮。
- 「我在这」只在自己的屏幕上显示，不公开。共享位置需要登录，可选模糊到约 1 公里，24 小时不更新就从地图消失。

## 短信验证码贵不贵

不贵，但不要把它当成没有防护的唯一入口。

国内验证码短信，腾讯云和阿里云大约每条 3 分到 5 分钱，以控制台当时的报价为准。这个站点如果只服务大陆手机号，不要开通国际短信，国际短信会贵一个数量级。

按每条 0.04 元、一次成功登录平均 1.3 条（含少量重发）粗算：

| 规模 | 当天需要收码的人 | 大约一个月 |
| --- | --- | --- |
| 日活 200 | 约两成，50 条/天 | 60 元上下 |
| 日活 2,000 | 约 500 条/天 | 600 元上下 |
| 日活 20,000 | 约 5,000 条/天 | 6,000 元上下 |

给朋友和第一批读者用，短信费可以忽略。真正会把账单打高的是脚本刷接口：没有频控时，一小时就能打掉一个月的预算。

途记已经做了这些限制：同一号码 60 秒一次、每天最多 8 次，同一 IP 每小时最多 60 次，验证码 5 分钟过期，错 5 次作废。登录态有 30 天，同一部手机不必天天收码。正式对公网开放前，再加一层图形或滑块验证码。

更适合国内用户的下一步，是把微信登录做成主按钮（开放平台网站扫码，或微信内网页授权），手机号留着绑定。微信登录的边际成本和短信比起来接近零，用户也少打字。当前版本按你要求的手机号验证码把登录做完整，短信通道可以以后接上，不需要重写账号体系。

演示环境设置 `DEMO_MODE=true`（默认就是），验证码只显示在页面上。正式环境：

```bash
DEMO_MODE=false
SMS_WEBHOOK_URL=https://你的短信函数地址
SMS_WEBHOOK_TOKEN=一串只有服务器知道的密钥
AUTH_SECRET=$(openssl rand -base64 32)
```

发码时会向 webhook POST `{ "phone", "code", "template": "login" }`。用腾讯云或阿里云的云函数去调短信 API 即可，签名和模板需要先通过审核。密钥不要放进仓库。

## 云服务器买什么

推荐腾讯云轻量应用服务器。这个产品和短信、对象存储、以后的微信分享域名校验可以放在同一家，备案和账号都省事。如果你已经有阿里云账号和短信资质，就继续用阿里云，不必为了换厂商再走一遍认证。两家都是一线，差别小于「地域和带宽有没有选对」。

面向国内普通用户、希望微信里打开得快：选上海或广州，并做 ICP 备案。个人可以备案。想先跳过备案、自己试用：选中国香港，同一规格，延迟会高一些。

起步规格：

- 2 核 vCPU
- 4 GB 内存
- 60 GB SSD 系统盘
- 带宽选轻量套餐里月流量 500 GB 到 1 TB、峰值 4 到 6 Mbps 这一档
- 系统 Ubuntu 24.04 LTS

不要先买 8 核。单机 Next.js 加 SQLite，2 核 4 GB 可以撑到每天几万次页面访问。地图瓦片来自外部，不占你的机器带宽。先不够的通常是图片和带宽，不是 CPU。

还要一起准备的：

- 一个域名
- 大陆节点的 ICP 备案
- HTTPS。仓库里的 Caddy 配置会自动申请 Let's Encrypt，不必单独买证书
- 短信签名和模板，按条计费
- 用户开始上传照片之后再开对象存储，不要把图片堆在系统盘

费用口径：轻量 2 核 4 GB 多数时候是每月几十到一百多元人民币，以购买页为准。域名每年几十元。对象存储在图片功能上线前可以是 0。短信见上一节。

什么时候再升级：内存长期高于七成，或要单独跑 PostgreSQL，就升到 4 核 8 GB，或把数据库拆出去。要开多台机器时，先把 SQLite 换成 PostgreSQL，前面再加负载均衡。图片变多时用对象存储加 CDN，不要靠升带宽硬扛。

## 部署

`Dockerfile` 可以直接构建。也可以在服务器上：

```bash
npm ci
npm run build
mkdir -p /var/lib/tuji
```

Next.js 的 standalone 产物需要带上静态文件：

```bash
cp -r .next/static .next/standalone/.next/static
cp -r public .next/standalone/public 2>/dev/null || true
```

用 `deploy/tuji.service` 和 `deploy/Caddyfile` 做进程和 HTTPS。环境变量放在 `/etc/tuji.env`，至少包括 `AUTH_SECRET`、`DEMO_MODE=false`、`TUJI_DATA_DIR=/var/lib/tuji`，以及短信 webhook。

定位功能要求 HTTPS，或在本地的 localhost 上使用。

## 正式上线前建议换掉的部分

- 地图：演示使用 OpenStreetMap 公开瓦片，坐标是 WGS84。国内产品应换成高德或腾讯地图，并处理 GCJ-02 与 WGS84 的差异。公开瓦片不适合正式流量，上线前要换成自己的地图服务。
- 数据库：单机继续用 SQLite。要多实例或多人同时写时换 PostgreSQL。
- 微信分享卡片：需要已认证的公众号或开放平台应用，配置 JS 安全域名后才能自定义好友卡片。现在的分享是链接、二维码和 QQ / 微博的网页分享。
- 图形验证码：频控已经在，公网开放前再加上。

## 技术栈

- Next.js、React、TypeScript
- Node.js 自带的 SQLite（`node:sqlite`）
- Leaflet，演示底图来自 OpenStreetMap
- 登录会话放在 HttpOnly Cookie 里，验证码只存哈希
